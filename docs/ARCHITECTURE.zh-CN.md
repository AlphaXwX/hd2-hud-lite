# 架构说明

## 数量、换弹与热量通道

针剂和手雷只读取本地角色类型已声明的标量字段，沿用现有 20 Hz 采样，
在死亡、角色／世界切换时清除；SVG 在构建时转为原生纹理，不增加运行时对象扫描。
已有换弹映射保持优先，无映射时用已声明的正换弹阶段开启经验证的角色第 11 动画层，
由实际 elapsed／length 提供进度。蓄力候选不再依赖热量候选。
未知热量上限保持隐藏，直到实际过热建立当前对象的观察参考。
仅已核对的蓄力／热量类型且无换弹阶段或动画映射时判为纯冷却，混合武器保留备弹。

## 运行流程

```text
Chef 更新 -> 受控原生采样 -> 身份识别 -> 信号提供层 -> 显示模型
          -> 可复用绘制命令 -> Chef 渲染
```

原生读取通常最高约每秒 20 次。两次原生读取之间，模型计算和视觉插值
使用最近缓存的采样结果。

## 模块职责

| 模块 | 职责 |
|---|---|
| `src/native.lua` | 受保护的引擎调用、单次采样缓存和生命周期清理 |
| `src/runtime.lua` | 身份识别、信号整合、容量下界及动画采样 |
| `src/draw.lua` | 圆环、独立图标、备弹横排和绘制插值 |
| `src/options.lua` | 可编辑选项，个人保存值优先 |
| `src/main.lua` | 分离 update、render 和 shutdown |
| `config/published_visual_defaults.json` | 已确认的 1920×1080 默认配置 |

## 显示逻辑

持枪和空手均在同一文字行显示 HP 与耐力。
能量充能使用右内环，右外环显示冷却就绪度。
信息行默认按针剂、手雷、归零、弹种、射速、弹匣数量、射击模式依次补位；
解锁后各项使用独立保存的 X／Y，不再因其他项缺失而移动。
归零优先使用武器／瞄具数据，元数据缺失时可由有效非默认选项建立当前对象的支持依据；
全零位本身不代表支持，明确移除或冲突元数据会清除该依据。
背包并入 Ring layout 使用直接数值和公共透明度／底环，不再有 0 自动或专用倍率模式。

信息行使用构建生成的 Alpha 边界去除 UV 透明留白，原纹理和图案自然显示比例不变。
排版与实际绘制采用相同边界，数量按量化后的实际像素高度居中；行横坐标与 HP／耐力文字独立。

动画换弹先通过手持武器的动画状态确认有效换弹，再读取本地人物的有效动画层。
使用动画时间及 clip、tail、base 计算归一化进度。
仅在绘制端进行短时插值，使离散样本看起来平滑，不用固定秒数替代真实动画。
换弹填充为白色。

## 生命周期与性能

- 世界或人物变化时，使旧引擎句柄及关联视觉状态失效。
- 通过类型、携带／绑定和手部挂点持续复验武器，不因无关归属列表变化、短暂断读或背包消失而清除有效手持。
- 客户端扫描主机装备仍受预算限制，必须由已声明 owner 匹配本地玩家，玩家／角色识别路径保持本地。
- 数据过期或通道不可用时隐藏，不编造数值。
- 新鲜的零血量、空弹匣和零备弹属于有效采样。
- 不可换弹类型不输出备用弹匣命令，但仍输出实际弹药；可换弹武器的真实零备弹仍有效。
- 新类型识别同时受次数上限和软耗时预算约束。
- 已识别且当前相关的候选不依赖轮转发现窗口；优先复验原手持／背包，并纳入已知竞争项，
  每轮额外已知候选复验最多 64 个。只保留身份依据，动态弹药仍重新采样。
- 复用采样读取和绘制容器，插值过程不调用引擎。
- 静态图只在新原生样本到达时重建，热量／蓄力仍逐帧计算，换弹平滑保留在绘制端。
- 输入与选项不变时复用行布局；文字宽度缓存上限 256 项并在一秒后失效，以适应加载器切换字体。
- 图片边界仅在构建时分析，游戏内不做图像分析；继续复用消耗品与布局容器。
- 不持有或销毁私有原生 GUI 句柄。

对外产品署名为 **HUD Lite / Alpha F. Bloodfallen**。
当前加载标识为 `mods/alpha_f_bloodfallen/hud_lite`，内部片段使用同一命名空间，
日志为 `hud_lite.log`，选项键保持 `hud.lite.*`。
每次原生调用前都以只读方式沿用 Chef 为本资源记录的中止和可疑调用；
不写入、也不清除任何 Loader 文件。

选项按十一类连续注册一次，使用可搜索前缀。Chef 1.2.3 不向模组提供折叠分组，
因此不注册假的标题项，不使用无效菜单 API，原配置键与保存值不变。
