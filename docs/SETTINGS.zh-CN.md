# 设置指南

[English](SETTINGS.md) · [中文文档索引](INDEX.zh-CN.md)

按 **F9** 打开 Chef 菜单，进入 **HUD Lite 1.0.1**。

## 菜单分类

同类设置按编号连续排列，标签带可搜索分类前缀。Chef 1.2.3 不向模组提供折叠分组，
因此不使用无效分组参数、假的标题开关，也不修改加载器。

| 前缀 | 内容 |
|---|---|
| 01 Display | 总显示、透明度、缩放与闲置亮度 |
| 02 Ring layout | 圆环位置、半径、线宽、弧长、底环与平滑，包含背包环 |
| 03 Vitals | 生命、耐力和组合文字 |
| 04 Ammunition | 弹药环、中央数字格式、字号与偏移 |
| 05 Weapon row | 信息行解锁、整行锚点、水平偏移、纵向位置与间距 |
| 06 Fire and ammo icons | 射击模式、弹种图标开关、大小与解锁位置 |
| 07 Zeroing and RPM | 归零、射速图标开关、大小与解锁位置 |
| 08 Reserves | 备弹位置、字号、弹匣图标和图文间距 |
| 09 Stims and grenades | 针剂、手雷开关、解锁位置与公共尺寸 |
| 10 Squad | 自身及队友增强图标 |
| 11 Animation | 换弹进度及平滑 |

原设置键与个人保存值保留；旧独立消耗品横排 X／Y 项忽略但不删除，仍采用 1920×1080 坐标。

## 紧凑武器信息行

默认锁定，从左向右固定顺序：**针剂 → 手雷 → 归零 → 弹种／功能 → 射速 → 弹匣数量 → 射击模式**。
隐藏、无数据和无纹理映射的图标不占位，只有一项时从行左端开始。
间距按图标／数量的可见边缘计算，不再把整块方形纹理的透明留白当作宽度。
构建时生成 UV 边界，保留原素材与自然显示大小；文字按加载器测量宽度和实际像素高度对齐。
背包备弹与武器备弹不重复绘制。

`hud.lite.row_x`、`hud.lite.fire_y`、`hud.lite.row_gap` 调整整行；
`hud.lite.row_x` 相对固定的已确认原点调整行左端，不再叠加实时 `hud.lite.info_x`；
后者只移动 HP／耐力文字。默认原点仍为圆环中心左侧 84 个设计单位，或所选的原版 HUD 锚点。
已保存的行 X 继续作为附加偏移，不重写、不重新解释其含义。
`hud.lite.fire_y` 只控制信息行纵向位置，不移动生命／耐力文字。
锁定时忽略各项 X／Y，只按可见宽度和行间距补位。
开启 **Unlock information row／信息行解锁**（`hud.lite.row_unlock`）后，可单独调整每项位置；
此时 X／Y 直接相对于公共行原点，不再叠加动态槽位。前项消失、开关变化或数量变宽均不会移动其他图标。
重新锁定会恢复自动补位，不删除手动位置；原保存的各项 X／Y 只在解锁时使用。
两种模式均可使用准星圆环附近或原版 HUD 锚点。

针剂使用 `cura`，手雷使用附件图标，两者都并入本行，空手同样显示。
真实零数量保留，无效／缺失读数隐藏。归零优先使用武器配置或已识别的瞄具配件。
配件元数据不可读时，有效非默认归零选择可为当前武器对象建立支持依据；该对象切回最低档后仍显示。
选择读数缺失、明确移除瞄具、元数据冲突、换武器或生命周期重置时，不保留失效图标。
全零位本身不代表支持，且不可换弹／纯供弹装备不使用此选择值回退。
若既无能力元数据，也未读到非默认归零选择，初始最低档图标仍隐藏，不猜测。

## 背包环设置

默认仍为右侧第三环，设置已并入 **02 Ring layout**，不再单独分类。
`backpack_x`、`backpack_y`、`backpack_radius`、`backpack_thickness`、`backpack_span`
均带 `hud.lite.` 前缀，与其他圆环使用相同的直接数值滑杆：X 相对屏幕中心，
Y 使用主圆环 Y 滑杆的设计坐标原点，不再相对主环偏移；半径、线宽、弧长不再以 0 表示自动。
默认 X **0**、Y **538**、半径 **168.5**、线宽 **3.5**、弧长 **73**。
缩放、透明度和底环统一使用公共设置，不再单列背包旋转、透明度倍率及独立底环。
移除项的旧保存值仅忽略，不删除；原背包位置／半径按新的直接数值含义使用，
如来自旧相对／自动布局，可在 Ring layout 内重新调整。不影响生命、弹药或换弹环。

右外环为弹药／冷却，右内环为换弹／蓄力，第三环为背包。
纯冷却及类型声明不可换弹的武器隐藏备用弹匣，包括共享字段报 0 的情况，但保留实际已装填弹药。
有真实换弹阶段／映射的单发武器、混合过热武器仍显示有效零备弹。
未知热量上限不硬设为 100，实际过热可建立观察参考；
缺少参考或未知蓄力时长时隐藏对应进度。

## 正式菜单精简

开发诊断、通道探测、内部状态显示、手动数据覆盖、扫描预算调试、人物搜索范围调试、
自动读取测试开关等，不再注册到玩家菜单。开发用参数改由内部固定限制控制。
已保存的旧测试项会被忽略，不删除或重写玩家的设置文件。

HP／耐力组合文字行只使用一个开关，旧的信息覆盖层开关不会强行把它重新开启。
未知弹匣容量不会从隐藏的手动覆盖设置中取得。

## 安全

删除开发设置不代表删除 Chef 的原生读取保护。
报错或通道不可用时，会隐藏依赖该数据的显示。
日志仍保留简洁的安全与错误提示，不显示面向玩家的诊断覆盖层。

## 多人装备识别

已确认的手持武器仍每次复验类型、携带／绑定状态、可读 owner 和本地手部挂点。
无关网络对象增减、列表短暂不可读、背包消失或延迟更新，不再在独立证明有效时强制重新识别整把武器。
弹药仍每次采样读取实时值，不冻结旧数量掩盖断读。

作为客户端时，可在有界扫描中检查网络上由主机持有的装备，但必须通过已声明 owner 匹配本地玩家。
不把主机玩家对象或角色作为本地替代。归属含糊、读取被保护、类型未知等情况仍会隐藏相关显示。
该路径尚需实机多人验证，模拟回归不代表对所有联机环境的保证。
